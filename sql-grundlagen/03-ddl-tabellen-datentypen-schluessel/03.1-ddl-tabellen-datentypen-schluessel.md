- Primärschlüssel (Primary Keys) und Fremdschlüssel (Foreign Keys) definieren

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **DDL** | Data Definition Language: `CREATE`, `ALTER`, `DROP` |
| **Datentyp** | legt Wertebereich und Speicher einer Spalte fest (`INTEGER`, `VARCHAR(n)`, `DATE`, `NUMERIC(10,2)`) |
| **`GENERATED ALWAYS AS IDENTITY`** | Spalte, deren Wert der Server aus einer Zählfolge vergibt; eigene Werte sind verboten |
| **Primärschlüssel (`PRIMARY KEY`)** | eindeutig und nie `NULL`; legt automatisch einen Index an |
| **Fremdschlüssel (`FOREIGN KEY`)** | verweist auf den Primärschlüssel (oder eine `UNIQUE`-Spalte) einer anderen Tabelle |
| **`UNIQUE`** | verbietet doppelte Werte; erlaubt mehrere `NULL` |
| **`NOT NULL`** | verbietet fehlende Werte |
| **`DEFAULT`** | Wert, der eingesetzt wird, wenn beim Einfügen keiner angegeben ist |

## Aufgabe

### Aufgabe 1 – CREATE TABLE (Einheit 3.1)

Lege in der Datenbank `firma` (über DBeaver als `labuser`) drei Tabellen mit diesen Spalten an: `abteilung` (`abteilung_id`, `name` Pflicht, `standort`), `mitarbeiter` (`mitarbeiter_id`, `vorname` Pflicht, `nachname` Pflicht, `email`, `gehalt`, `abteilung_id`) und `projekt` (`projekt_id`, `bezeichnung` Pflicht, `startdatum`, `abteilung_id`). Verwende sinnvolle Datentypen (z. B. `VARCHAR`, `INTEGER`, `DATE`, `NUMERIC(10,2)` für das Gehalt). Die Schlüsselspalten `..._id` werden als `INTEGER GENERATED ALWAYS AS IDENTITY` angelegt. Die Spalte `abteilung_id` in `mitarbeiter` und `projekt` bleibt ohne `NOT NULL`. Alle späteren Module verwenden diese Namen. Speichere die Befehle in einem DBeaver-Skript `01_struktur.sql`.

### Aufgabe 2 – Constraints definieren (Einheit 3.3)

Ergänze die Tabellen um Primärschlüssel (`..._id`). Erstelle in `mitarbeiter` und in `projekt` je einen Fremdschlüssel auf `abteilung` und lege auf `mitarbeiter.email` eine `UNIQUE`-Bedingung.

### Aufgabe 3 – ALTER TABLE (Einheit 3.2)

Ändere die Tabelle `mitarbeiter` nachträglich ab und füge eine Spalte `einstellungsdatum` (`DATE`) hinzu, die nicht `NULL` sein darf (Tipp: Verwende den Default-Wert `CURRENT_DATE`).

### Aufgabe 4 – DROP TABLE (Einheit 3.2)

Lege eine Hilfstabelle `temp_test` (eine Spalte `x INTEGER`) an und lösche sie mit `DROP TABLE temp_test;` wieder. Prüfe im DBeaver-Navigator (Aktualisieren), dass sie verschwunden ist.

## Hinweise

- Die Spaltennamen sind festgelegt, weil alle späteren Module sie verwenden: `abteilung` (`abteilung_id`, `name`, `standort`), `mitarbeiter` (`mitarbeiter_id`, `vorname`, `nachname`, `email`, `gehalt`, `abteilung_id`, ab Aufgabe 3 `einstellungsdatum`), `projekt` (`projekt_id`, `bezeichnung`, `startdatum`, `abteilung_id`).
- Lege zuerst `abteilung` an, bevor ein Fremdschlüssel darauf verweist.
- `ALTER TABLE … ADD COLUMN … NOT NULL` braucht einen `DEFAULT`, wenn die Tabelle schon Zeilen hat; neue Spalten erhalten den Default in allen vorhandenen Zeilen.
- **Lücken in den Identity-Werten sind normal:** Auch ein **fehlgeschlagenes** `INSERT` verbraucht einen Wert (Test an einer temporären Hilfstabelle: Fehlversuche verbrauchten die Werte 1, 2 und 4). Die Muster-Daten der späteren Module setzen deshalb nie voraus, dass die IDs lückenlos sind; den Wert liefert `INSERT … RETURNING mitarbeiter_id`.
- Probiere Fehler (Verstöße gegen Constraints) an einer **Hilfstabelle** aus, nicht an `mitarbeiter`; sonst entstehen Lücken in den IDs der Kurstabellen (siehe oben).
- DBeaver führt Befehle standardmäßig sofort fest aus (Auto-Commit, nicht bestätigt); `psql` tut das ebenfalls.

**Aufgabe 1 (CREATE TABLE).** Das Skript `01_struktur.sql` (Teile 1 und 2) legt die drei Tabellen mit `INTEGER GENERATED ALWAYS AS IDENTITY` für die Schlüsselspalten an. Kontrolle (Auszug, echte Ausgabe):

```text
firma=> \d mitarbeiter
 mitarbeiter_id    | integer                | not null | generated always as identity
 vorname           | character varying(50)  | not null |
 nachname          | character varying(50)  | not null |
 email             | character varying(100) |          |
 gehalt            | numeric(10,2)          |          |
 abteilung_id      | integer                |          |
```

`abteilung_id` bleibt in `mitarbeiter` und `projekt` ohne `NOT NULL` (Modul 7 braucht einen Mitarbeiter ohne Abteilung).

**Aufgabe 2 (Constraints definieren).** Die Constraints stehen im selben Skript (`ALTER TABLE … ADD CONSTRAINT pk_… PRIMARY KEY`, `fk_…`, `uq_mitarbeiter_email`). `\d mitarbeiter` zeigt danach:

```text
Indexes:
    "pk_mitarbeiter" PRIMARY KEY, btree (mitarbeiter_id)
    "uq_mitarbeiter_email" UNIQUE CONSTRAINT, btree (email)
Foreign-key constraints:
    "fk_mitarbeiter_abteilung" FOREIGN KEY (abteilung_id) REFERENCES abteilung(abteilung_id)
```

**Fehlerfälle** (an temporären Hilfstabellen `t_abt`, `t_mit`, echte Meldungen): Fremdschlüssel auf einen fehlenden Wert: `violates foreign key constraint … DETAIL: Key (abt)=(99) is not present in table "t_abt"`. Fehlendes Pflichtfeld: `null value in column "nachname" … violates not-null constraint`. Eigener Wert für eine `GENERATED ALWAYS`-Spalte: `cannot insert a non-DEFAULT value into column "id"` (Hinweis: `OVERRIDING SYSTEM VALUE`). Doppelte E-Mail: `duplicate key value violates unique constraint`. Mehrere Zeilen mit `NULL` in der `UNIQUE`-Spalte sind erlaubt.

**Aufgabe 3 (ALTER TABLE).**

```sql
ALTER TABLE mitarbeiter ADD COLUMN einstellungsdatum DATE NOT NULL DEFAULT CURRENT_DATE;
```

Ohne `DEFAULT` würde der Befehl bei vorhandenen Zeilen scheitern; mit leerer Tabelle geht beides. Die Spalte steht in `\d mitarbeiter` als `einstellungsdatum | date | not null | CURRENT_DATE`.

**Aufgabe 4 (DROP TABLE).**

```text
CREATE TABLE temp_test (x INTEGER);
DROP TABLE temp_test;
\dt       (davor: 4 Tabellen, danach: abteilung, mitarbeiter, projekt)
```

In DBeaver zeigt der Navigator die Tabelle erst nach „Aktualisieren“ nicht mehr (nicht getestet). **Ergänzung (CHAR/VARCHAR, echte Ausgabe):** `'ab'::char(5)` belegt 5 Byte, `'ab'::varchar(5)` 2 Byte; `'ab'::char(5) = 'ab   '::char(5)` ergibt `t`, bei `varchar` `f`.

**Fragen.** (1) DDL steht für **Data Definition Language**. Dazu gehören `CREATE`, `ALTER` und `DROP` (je nach Einteilung auch `TRUNCATE`). (2) `CHAR(50)` hat eine **feste Länge**: kürzere Werte werden mit Leerzeichen aufgefüllt (im Test belegt `'ab'::char(5)` 5 Byte, und das Auffüllen wird beim Vergleich ignoriert). `VARCHAR(50)` speichert nur die tatsächliche Länge bis zum Maximum (2 Byte für `'ab'`; Leerzeichen am Ende zählen beim Vergleich mit). (3) Die referenzierte Spalte muss ein **Primärschlüssel** oder `UNIQUE` sein; beide Spalten brauchen kompatible Datentypen; die Zieltabelle muss existieren; jeder Wert in der Fremdschlüsselspalte muss in der Zieltabelle vorkommen (oder `NULL` sein, wenn die Spalte das erlaubt).

## Lernziele

Nach dieser Übung kannst du

- NoSQL-Arten nennen und vom relationalen Modell abgrenzen
- einen Redis-Server starten und prüfen
- Schlüssel setzen, lesen, suchen und löschen

- Datenbankgrundlagen

| Begriff | Bedeutung |

## Hinweise

- Das Skript startet Redis auf `127.0.0.1` (Port 6399, teils 6400) und beendet es am Ende; belegte Ports vorher prüfen.
- Alle Daten sind erfunden; die Dateien liegen unter `/tmp/p67`.

## Kontrollfragen

1. Was ist das Schlüssel-Wert-Modell?
2. Warum Doppelpunkte in Schlüsselnamen?
3. Was liefert `PING`?
4. Wann ist Redis gegenüber SQL ungeeignet?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. Siehe `beispiele/start.ausgabe.txt`: Version 7.0.15, `PONG`, `redis_mode:standalone` (einzelner Server ohne Cluster), Port 6399.
2. `SCAN` liefert Schlüssel schrittweise und blockiert den Server nicht lange, `KEYS` durchsucht alles auf einmal (Fachwissen). Nach `DEL kunde:2:name` liefert `EXISTS` für diesen Schlüssel 0, für `kunde:1:name` 1; `DBSIZE` zeigte vorher 2 Schlüssel.

**Kontrollfragen (Antwortskizzen):**

1. Zu einem Schlüssel gehört ein Wert; Zugriff meist nur über den Schlüssel.
2. Eine Namenskonvention, die Gruppen erkennbar macht (`kunde:1:name`).
3. `PONG`, wenn der Server erreichbar ist.
4. Bei komplexen Abfragen und Verknüpfungen (Fachwissen).

</details>

## Erweiterungen

- Weitere Schlüssel mit eigener Namenskonvention anlegen und mit `SCAN` auflisten.
- Redis-Server mit `--port` auf einem anderen Port starten.
